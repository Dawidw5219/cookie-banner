# Cookie Banner 2.0.0

## Zmiany

- Wspólny rdzeń npm i WordPress: odświeżony popup i blokery filmów/iframe’ów.
- Wymagane informacje administratora, celów i dostawców; niekompletne usługi pozostają zablokowane.
- Wersjonowane decyzje, rejestr WordPressa z eksportem i retencją, cofnięcie jednym kliknięciem, czyszczenie wskazanych identyfikatorów oraz natychmiastowe ograniczenie sieci przed przeładowaniem.
- Dziesięć języków interfejsu i blokerów, własne treści per język, regionalne fallbacki i adaptery WPML/Polylang.
- Dwa style przycisków: ścisły (`equal`, domyślny) i standardowy (`standard`). To wybór wyglądu; blokowanie i odmowa działają w obu wariantach.

## Dawid — npm i strony IVF

@Dawidw5219 publikację npm zostawiamy Tobie. Kod pakietu i wtyczka mają wersję **2.0.0**.

**Na stronach IVF, jeśli akceptacja i odmowa mają wyglądać inaczej, dodaj do istniejącej konfiguracji:**

```js
buttonStyle: 'standard'
```

Wtedy akceptacja ma pełne wypełnienie, a odmowa obrys. Bez parametru obowiązuje ścisły wariant z identycznymi przyciskami (`equal`). Parametr działa też w zwykłym JS i Next.js; nie trzeba używać WordPressa.

Po pobraniu `main`: `bun install`, `bun run build`, `bun run test`, `bun run typecheck`, `bun run test:package`, a następnie `npm publish --access public`. Potwierdź publikację przez `npm view cookie-banner@2.0.0 version` i dopiero wtedy zaktualizuj zależność na stronach IVF.

Migracja wymaga prawdziwych danych administratora, celów, polityk i informacji o usługach. Skrypty kategorii wymagają również ID `service`; zgoda na samą kategorię nie uruchamia dostawcy. Instrukcje: [migracja](../consent-compliance.md), [integracja](../consent-integration.md), [języki](../multilingual.md).

## Weryfikacja i ograniczenia

90 testów rdzenia, 4 testy słownika panelu, typecheck npm i panelu, test rzeczywiście spakowanego npm (SSR, NodeNext/Bundler) oraz 19 scenariuszy przeglądarkowych ochrony i obu stylów przycisków. Osobno sprawdzono 10 języków npm i rzeczywisty Polylang EN/PL/DE, edytor wersji językowych, zapis decyzji oraz przejście między językami.

Elementor z WP Rocket i LiteSpeed Cache sprawdzono z opóźnianiem/łączeniem skryptów; zakres i środowiska opisują raporty w `docs/research/`. WP Rocket był oficjalnym kodem GPL z lokalną zmianą warunku licencji do testów optymalizatorów; usług licencyjnych/chmurowych nie testowano. WPML sprawdzono przez kontrakty jego filtrów, bez zainstalowanej wtyczki WPML. Ostatnia dodatkowa próba otwarcia panelu zakończyła się timeoutem lokalnego wp-admin; zapis trybu potwierdzono przez uwierzytelniony REST.

To mechanizmy wspierające poprawne wdrożenie, nie certyfikat zgodności prawnej dowolnej witryny. Przed aktualizacją zapoznaj się z migracją i sprawdź własny CDN, konfigurację oraz informacje prawne.
